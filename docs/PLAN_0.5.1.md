# План 0.5.1 (не начат)

## Главное

### SoundCloud заблокирован — честно сказать и предложить обход
Из отчёта FEEDBACK #SY-4A934FC3 (Станция Лайт, 2026-11-08): обновление 0.4.42 → 0.5.0 прошло,
но музыка не играет. `soundcloud.com` в сети пользователя заблокирован (TLS-рукопожатие обрывается:
`tls connection init failed: Resource temporarily unavailable (os error 11)`), а `api-v2` отвечает.
SoundCloud сменил `client_id`, взять новый можно только с `soundcloud.com` → 401 → «ключ сайта
сменился, а soundcloud.com не открылся за новым». Обход блокировок у пользователя выключен.

Сейчас панель при этом показывает «Сеть: хорошая» и вечное «проверяю вход» — человек не понимает,
что делать.

Сделать:
- `check_login` / `sc.rs`: запоминать причину неудачи; если `soundcloud.com` не открывается
  (ошибка соединения/TLS), а API отвечает — состояние входа «blocked», а не «checking».
- `/api/status`: `login_error` (текст причины) и `login: "blocked"`.
- Панель: вместо «проверяю вход» — «soundcloud.com заблокирован в вашей сети — включите обход
  блокировок» и кнопка, которая сразу запускает «Подобрать автоматически» (Соединение → Обход).
- Индикатор сети не должен говорить «хорошая», когда сайт SoundCloud недоступен.
- Голос: на «Алиса, включи …» в такой ситуации — та же подсказка, а не «не получилось».
- Тест: имитация «API отвечает 401, soundcloud.com не открывается» → состояние «blocked».

### Будильник, который не проспать (сейчас только в dev-сборке)
`src/alarm.rs`, `dev/alarm.js`. «Алиса, разбуди меня в 7 под мои лайки» → музыка → Алиса «пора вставать» →
«Вы проснулись?» → без ответа снова, громче. Выключается только «Алиса, я проснулся» + верный ответ на
пример; «стоп», пауза, ▶‖ не выключают; «ещё 5 минут» — 2 раза; перезапуск колонки звонок не сбрасывает.
Перед выпуском: проверить на колонке (громкость, музыка при плохой сети, Алиса не перебивает своим
будильником), перенести блок с панели из dev/alarm.js в web.html и убрать `cfg(feature = "dev")`.
