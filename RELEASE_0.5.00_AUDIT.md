## 1. Архитектура (подтверждено кодом)

- **Один бинарник** Rust 2021, `opt-level="z"`, `lto="fat"`, `panic="abort"`,
  `strip`. Зависимости: `ureq` (tls, json, socks), `serde`/`serde_json`,
  `symphonia` (mp3/aac/mp4), `webpki-roots`. Async нет — потоки и
  `std::sync::mpsc`. Переводить на Tokio **не нужно**: нагрузка — единицы
  соединений, а размер бинарника и RAM колонки важнее.
- **`Controller` (main.rs)** — единственный владелец состояния плеера
  (очередь, позиция, `generation`, флаги трека). Всё, что меняет плеер, приходит
  как `Cmd` по одному каналу; медленное (сеть SoundCloud, ПК, ТВ, обход)
  выполняется в отдельных потоках и возвращается сообщением. Гонок по состоянию
  плеера нет by design.
- **Общие флаги** — `Shared` (Atomic*/Mutex): что играет, «Алиса занята»
  (приглушение), кэш JSON статуса для панели (панель не ждёт контроллер).
- **Голос (alice.rs)** — TCP к локальному Quasar IPC `127.0.0.1:9875`
  (протокол из spotiya): распознанные фразы → `intent()` → решение «чьё»
  (с 0.5.00 — чистая функция `owns()`) → `cancel_alice()` и `Cmd::Voice`.
  Озвучка — START_VOCALIZE.
- **Порты на колонке:** `8765` — веб-панель (`0.0.0.0`, без авторизации);
  `127.0.0.1:47895` — управляющий порт для CLI `soundya …`; `5000` — AirPlay
  (shairport-sync). **`8787` — не на колонке**: это сервер статистики и
  обратной связи автора (`server/stats.py`), колонка туда только ходит.
- **Фоновые потоки:** led (40–50 мс тик), alsa watch, mdns, airplay,
  stats (раз в сутки), luna, zapret, update (каждые 10 мин проверка «пора ли»,
  GitHub — раз в 6 ч), clock, report (0.5.00), веб — поток на соединение.
- **Хранилище:** `/data/opt/soundya/` — `config.json` (настройки и секреты),
  `client_id`, `adbkey*`, `history.json`, `install_id`, `soundya.env`, логи
  на флеше (`last.log`, `previous.log`, `guard.log`, `audio-errors.log`).
  `/tmp/soundya.log` — текущий лог (tmpfs).
- **Автозапуск:** `/etc/init.d/S99soundya` → `run.sh` (перезапуск через 3 с
  после любого выхода, 20 с паузы после загрузки) + `guard.sh` (лог на флеш,
  спасение зависшей звуковой карты).
- **Panel:** `web.html` (~118 КБ) вшит `include_str!`, без внешних ресурсов.

## 2. Состояние функций

### 2.1 Реализовано и работает (по коду и тестам; на колонке — со слов автора и README)
- SoundCloud: поиск, треки, плейлисты, альбомы, лайки и плейлисты аккаунта
  (чтение), рекомендации, «похожее», автопродолжение, перемотка, повтор,
  перемешивание, история, обложка через колонку, дозагрузка при обрыве.
- Голосовые команды музыки, «что играет», ПК, ТВ, сообщения контактам —
  покрыты юнит-тестами `alice.rs` (расширены в 0.5.00).
- Приглушение музыки, пока Алиса слушает/говорит (`Duck`, 20 %).
- AirPlay **1** (classic RAOP) через shairport-sync 5.6.2, своя реализация
  mDNS-анонса, подстройка скорости под карту, приглушение под голос Алисы.
- ТВ (Android TV по сетевому ADB, свой RSA-ключ): разбудить/усыпить, открыть
  приложение по имени (`pm list packages` + транслитерация), поиск, YouTube,
  кнопки пульта.
- ПК (Windows, PowerShell-агент): WoL, сон/выкл/перезагрузка/блокировка,
  открыть/закрыть программу, браузерные профили, заметки, документы, Telegram
  Desktop, VPN. Ключ в заголовке, файрвол — LocalSubnet.
- Подсветка: Lite (sysfs, 3 зоны), Mini 2 (sysfs, 6), Mini 1 (I²C-чип),
  Mini 3 (framebuffer), Luna API; режимы ровный/пульс/эквалайзер.
- Обход блокировок (встроенные стратегии + zapret nfqws/nfqws2), прокси.
- Обновление с GitHub из панели, установка через `install.sh`.
- Анонимная статистика, сервер статистики со страницей.
- Из `release-0.4.41`: голосовые макросы, бот приёма в сообщество, баннер
  «100+» на странице статистики, `/api/stream` (звук трека в браузер).

### 2.2 Реализовано, но работало некорректно (исправлено в этой ветке — см. §3)
- Эквалайзер снижал общую громкость (Б-1).
- Цвета кольца Mini 2 (Б-2).
- Обратная связь терялась при недоступном сервере/Telegram, без диагностики (Б-3).
- Сохранение настроек: потеря при сбое питания, сброс к умолчаниям (Б-4, Б-5).
- Обновление без резервной копии, проверки запуска и отката (Б-6).
- Маршрутизация музыки: «устаревшее» состояние SoundCloud перехватывало
  команды для музыки Алисы (Б-7).
- CSRF / DNS-rebinding на панели (Б-8).

### 2.3 Реализовано частично
- **ТВ:** нет списка приложений в панели, нет закрытия приложений, нет
  визуального редактора последовательностей (макросы 0.4.41 — текстовые, через
  CLI/`macro add`, в панели редактора нет).
- **ПК:** нет метрик (CPU/GPU/RAM/температура), нет проверки процессов, нет
  сценариев в панели. Ключ передаётся открытым текстом по HTTP (в LAN).
- **Telegram:** только отправка через Telegram Desktop на ПК (агент печатает
  в окно). Своего клиента на колонке нет, уведомлений нет.
- **SoundCloud-вход:** ручное копирование cookie `oauth_token`; протухание
  определяется (`token_bad`) и озвучивается, но в панели нет явного статуса
  «войдите заново».
- **Бот сообщества:** правила, согласие, Telegram ID, время, версия правил —
  есть (`consents.jsonl`). Нет: обработки заявок на вступление
  (`chat_join_request`), кнопки «Отказываюсь», админ-статистики и модерации;
  общая ссылка-фолбэк может быть переслана в обход согласия.
- **Баннер 100+:** есть на странице статистики (живое число `DATA.ever`), в
  панели колонки — нет. У сервера нет CORS, поэтому панель должна брать число
  через колонку, а не из браузера.
- **Макросы:** только голосовая фраза → список команд; редактор в панели
  отсутствует.

### 2.4 Не реализовано
Smart Audio Ducking по внешним событиям (звонки, уведомления), Smart Display и
виджеты, новые анимации (волна, радуга, бегущий огонь…), onboarding и мастер
первой настройки, гибкий автозапуск сценариев, планировщик и Google Calendar,
Bluetooth-вывод, Audio Hub и мультирум, Telegram-клиент на колонке, новый
дизайн панели, «Использовать Яндекс Музыку» как явный переключатель
(сделан в этой ветке как «Музыка по умолчанию»).

### 2.5 Ограничено оборудованием/платформой
- **AirPlay 2:** собран AirPlay 1. AirPlay 2 у shairport-sync требует
  `--with-airplay-2`, демона **nqptp** (порты 319/320, root), libplist,
  libsodium, libgcrypt и FFmpeg (декод ALAC/AAC) — для статической armv7-сборки
  это +несколько МБ и отдельный постоянный процесс. Возможно, но не проверено;
  до проверки — только «AirPlay».
- **Яндекс Музыка:** soundya не видит её плеер (только то, что Алиса начала
  «своё»); назвать её трек или управлять её очередью он не может — только
  уступить фразу Алисе.
- **Голос:** только через распознанный Алисой текст. Свой микрофонный анализ
  не нужен и не используется (это же — принцип для Ducking).
- **Smart Display:** у Мини 2 «с часами» есть цифровой экран, но способ управлять им из
  Linux (sysfs/фреймбуфер/драйвер) в коде и документации проекта не найден —
  требует исследования на устройстве. На Lite/Mini 1 — только кольцо.
- **Bluetooth A2DP source:** зависит от BT-стека прошивки (наличие bluez/
  собственного стека, профиль source). В коде проекта ничего нет.
- **Мультирум:** нет общего источника времени между колонками; синхронность
  обещать нельзя без замеров.

### 2.6 Требует исследования на устройстве
Версия прошивки (`report.rs::firmware()` пробует `build.prop` и
`quasar.cfg`, но на каких моделях это заполнено — неизвестно);
`max_brightness` колец Лайт и Мини 2; правильность перестановки R/B на Мини 2
(коммит автора `8f3c73c`) на всех ревизиях; экран Мини 2; BT-стек;
потребление RAM/CPU (`diagnostics.json` теперь это собирает).

## 5. Обновление и сохранность данных — как теперь устроено

1. Сборка кладёт в пакет `VERSION` и `SHA256SUMS`.
2. `update.rs` сверяет скачанный архив с `digest` (sha256), который GitHub
   отдаёт для файлов релиза, если он есть; иначе — размер, как раньше.
3. `install.sh`: проверка `SHA256SUMS` и того, что новый бинарник запускается
   на этой колонке → копия программы в `backup/prev` и данных в
   `backup/data-<время>-<версия>` (хранятся 5) → замена **только** файлов
   программы → старт → ожидание `/run/soundya.ready` с новой версией и
   PID, затем проверка, что процесс жив и отвечает → иначе откат программы
   **и данных** к состоянию до обновления.
4. Итог — в `update-result` (ok / rolledback / failed + причина), панель
   показывает его в «Обновления».
5. Демон при старте мигрирует `config.json` (копия старого — `config.v<N>.json`),
   неизвестные поля новой версии сохраняет (откат им не вредит).
